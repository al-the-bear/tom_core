# tom_md2pdf bridge

The `tom_md2pdf` bridge exposes the Tom Framework Markdown→PDF converter
(`package:tom_md2pdf`) to D4rt scripts — the static convenience API, the
file/directory converter, and the D4rt-friendly PDF-options value model. Bridges
are generated by `d4rtgen` into
`lib/src/tom_md2pdf/tom_md2pdf_bridges.b.dart` and registered through
`TomDartscriptBridges.register` (see [`README.md`](../README.md)).

Scripts reach this surface by importing the upstream barrel:

```dart
import 'package:tom_md2pdf/tom_md2pdf.dart';
```

The bridge covers all 3 source files exported by `tom_md2pdf.dart`
(8 classes + 1 enum; no globals or top-level functions).

## Modules

### Convenience API

| Class | Purpose |
| ----- | ------- |
| `Md2Pdf` | Static one-call API (all async): `convertString`, `convertFile`, `convertFileToBytes`. |

### File & directory converter

| Class | Purpose |
| ----- | ------- |
| `MdPdfConverter` | The conversion engine. |
| `MdPdfConverterOptions` | Conversion options (document/page settings). |
| `MdPdfConverterResult` | Directory-conversion statistics (`isSuccess`). |
| `PdfConvertedFile` | A converted file's source + output paths. |
| `PdfConversionError` | A per-file conversion failure (`sourcePath`, `message`). |

### PDF options value model

| Class / Enum | Purpose |
| ------------ | ------- |
| `PageFormat` (enum) | `a3`, `a4`, `a5`, `letter`, `legal`, `tabloid` (6 values); instance method `toPdfPageFormat`. |
| `PageMargins` | Numeric page margins (`top`/`right`/`bottom`/`left`, default 72.0); constructors `()`, `.all(value)`, `.symmetric(...)`. |
| `PdfConverterOptionsWrapper` | D4rt-friendly options carrier using simple types (`title`, `author`, `pageFormat`, `margins`, `fontSize`, `fontFamily`, `excludePatterns`). |

## Example

```dart
import 'package:tom_md2pdf/tom_md2pdf.dart';

main() {
  // The D4rt-friendly options value model — no IO, no PdfPageFormat.
  var margins = PageMargins.symmetric(horizontal: 36, vertical: 54);
  var opts = PdfConverterOptionsWrapper(title: 'Report', pageFormat: 'a5');

  return [PageFormat.values.length, margins.top, opts.pageFormat];
  // [6, 54.0, 'a5']
}
```

## Tests

Bridge coverage lives in
[`test/replay/test_d4rt_tom_md2pdf.d4rt`](../test/replay/test_d4rt_tom_md2pdf.d4rt),
run via the replay harness (`d4rt -run-replay <file> -test`, see
[`doc/testing.md`](testing.md)). The suite exercises the `PageFormat` enum
(6 values + `.name`), the `PageMargins` value carrier (defaults + `.all`/
`.symmetric` named constructors + the four getters), the
`PdfConverterOptionsWrapper` defaults and getters, the
`PdfConvertedFile`/`PdfConversionError`/`MdPdfConverterResult` carriers, and
class-existence for `Md2Pdf`/`MdPdfConverter`/`MdPdfConverterOptions`.

> **Status (refactoring pass):** the bridge was regenerated 2026-06-15 from the
> upstream `tom_md2pdf` barrel (pubspec `version: 1.0.0`), which exports 3 source
> files. The bridge maps the full surface — 8 classes + 1 enum (`PageFormat`),
> no globals/functions. There was no pre-existing replay test; one was authored
> from scratch.
>
> The surface was verified **at the d4rt level** via an isolated single-bridge
> harness (register only `TomMd2pdfBridge`, then `d4rt.execute` a script
> importing `package:tom_md2pdf/tom_md2pdf.dart`) under the resolved
> `tom_d4rt 1.8.23` — the script builds `PageMargins(...)`/`PageMargins.all`,
> `PdfConverterOptionsWrapper()`, `PdfConvertedFile`/`PdfConversionError`/
> `MdPdfConverterResult`, and reads the `PageFormat` enum, returning the expected
> `[6, a4, letter, 10.0, 40.0, 5.0, a4, 12.0, Roboto, s.md, o.pdf, boom, true]`.
> This confirms the bridge is **d4rt-loadable with no codegen defect** — the
> upstream package has **no `part of` files**, so there is no B4-style
> part-import that the CFE rejects. (`pubspec.lock` is gitignored; `tom_d4rt: any`
> resolves to 1.8.23, so the B1 lock-pin blocker does not apply.)
>
> **Generator gap — enum static methods not bridged.** `PageFormat.fromString`
> is a *static* method on the enum; the generator emits only the enum's
> *instance* methods (`toPdfPageFormat`) into `BridgedEnumDefinition.methods`,
> so `PageFormat.fromString('letter')` throws *"Undefined property or method
> 'fromString' on BridgedEnum"* in d4rt. The replay test avoids it (uses
> `PageFormat.letter.name` directly). This is a `d4rtgen` limitation to track on
> the generator, not a per-bridge defect.
>
> **No B2 clash.** Unlike `tom_doc_scanner`/`tom_md2latex`, this bridge does
> **not** register a `MarkdownParser` (the htmltopdfwidgets-based converter does
> its own HTML/PDF rendering and re-exports none of the markdown parser types).
> Its class names (`Md2Pdf`, `MdPdfConverter*`, `Pdf*`, `PageFormat`,
> `PageMargins`, `PdfConverterOptionsWrapper`) are unique across all bridges, so
> the full-binary `d4rt -run-replay` introduces no cross-module duplicate-name
> collision here. `dart analyze lib/src/tom_md2pdf` clean.
