# tom_core_server bridge

The `tom_core_server` bridge exposes the Tom Framework server kernel
(`package:tom_core_server`) to D4rt scripts — authentication, authorization
caching, configuration, datasources/SQL, database migration, endpoint
routing, health checks, object persistence (the query DSL + repositories),
the HTTP server, and transaction management. Bridges are generated by
`d4rtgen` into `lib/src/tom_core_server/tom_core_server_bridges.b.dart` and
registered through `TomDartscriptBridges.register` (see
[`README.md`](../README.md)).

Scripts reach this surface by importing the upstream barrel:

```dart
import 'package:tom_core_server/tom_core_server.dart';
```

## Re-exported surfaces

The server barrel re-exports three upstream packages, so their bridged
classes are reachable through `tom_core_server` too:

| Package | Doc | Examples |
| ------- | --- | -------- |
| `tom_core_kernel` | [`tom_core_kernel.md`](tom_core_kernel.md) | the whole kernel surface (which itself re-exports `tom_basics`, `tom_crypto`, `tom_reflection`) |
| `mysql_client` | (upstream) | `MySQLConnection`, `MySQLConnectionPool`, column-type/packet types |
| `tom_basics_console` | (upstream) | standalone platform detection |

The remainder of this document covers the classes the server **owns**.

## Example

```dart
import 'package:tom_core_server/tom_core_server.dart';

main() {
  // A server exception (clientThrow defaults to true, autoLog to false).
  var ex = TomServerException('SRV_DOWN', 'Service unavailable');

  // Query-DSL literals expose their wrapped value via operant1.
  var name = StringLiteral('ada');
  var age = IntegerLiteral(42);

  // (Typed config keys such as TomStringConfig('app.name') resolve their value
  // eagerly and require a registered configuration resource — see above.)

  return [ex.key, ex.clientThrow, name.operant1, age.operant1];
  // ['SRV_DOWN', true, 'ada', 42]
}
```

## Tests

Bridge coverage lives in
[`test/replay/test_d4rt_tom_core_server.d4rt`](../test/replay/test_d4rt_tom_core_server.d4rt),
run via the replay harness (`d4rt -run-replay <file> -test`, see
[`doc/testing.md`](testing.md)). The suite exercises the cache types
(`TomCacheEntry`/`TomCacheManager`/`TomCacheException`), the auth/login
exceptions, the cmdline/config utility classes, `TomServerException`, the
query-DSL literals (`StringLiteral`/`IntegerLiteral`), and a typed config.

> **Status (refactoring pass):** the bridged surface above was verified against
> the local `tom_core_server` source (pubspec `version: 1.1.0`; bridge
> regenerated 2026-06-15 from 38 source files). The documented/tested API was
> additionally exercised **natively** (plain-Dart construction, no d4rt) —
> `TomServerException`, the query-DSL literals, the cache/auth exceptions and
> cache types all behave as documented (12/12 native assertions pass). One
> finding: `TomStringConfig`/`TomIntConfig` resolve their value eagerly and
> throw without a registered configuration resource, so the replay suite only
> verifies their class symbols rather than constructing them. The replay test
> could **not** be runtime-executed through the bridge (in isolation or as part
> of the full registration) for three reasons that are all deferred to the
> project-wide registration-verify and analyze/replay items:
>
> 1. The committed `pubspec.lock` pins `tom_d4rt 1.8.10`, but the generated
>    bridges target the newer `BridgedClass` API (`isAssignable`/
>    `hierarchyDepth`), which requires `tom_d4rt >= 1.8.19`.
> 2. The full registration hits a cross-module `MarkdownParser`
>    duplicate-registration clash.
> 3. The committed `tom_core_server` bridge itself has **two generation
>    defects** that prevent it compiling even against `tom_d4rt 1.8.23`: a
>    spurious top-level `main` global is registered against
>    `cache/server_cache.dart` (which declares no `main`), and the MariaDB
>    `withConnection` callback is generated with a `FutureOr<Object?>` vs
>    `FutureOr<Object>` variance mismatch. Both must be fixed in the
>    generator/runtime and the bridge regenerated before the server replay
>    suite can run.
