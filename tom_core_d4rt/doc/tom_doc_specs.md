# tom_doc_specs bridge

The `tom_doc_specs` bridge exposes the Tom Framework document-schema toolkit
(`package:tom_doc_specs`) to D4rt scripts — the DocSpecs scanner, the typed
spec section/document model, the schema definitions, the schema loader/expander,
the skeleton generator, and the validation pipeline. Bridges are generated by
`d4rtgen` into `lib/src/tom_doc_specs/tom_doc_specs_bridges.b.dart` and
registered through `TomDartscriptBridges.register` (see [`README.md`](../README.md)).

Scripts reach this surface by importing the upstream barrel:

```dart
import 'package:tom_doc_specs/tom_doc_specs.dart';
```

The bridge covers all source files exported by `tom_doc_specs.dart` (29 classes,
2 enums; no globals or top-level functions), plus the re-exported `Section` and
`Document` from `tom_doc_scanner`.

## Modules

### Main API & spec model

| Class | Purpose |
| ----- | ------- |
| `DocSpecs` | Scans a markdown document against a schema (`scanDocument`), exposing typed/validated access. |
| `DocSpecsFactory` | Constructs configured `DocSpecs` instances. |
| `SpecSection`, `SpecDoc` | A validated section + the document root. |
| `SpecSectionType` | Grouped access to all sections of a given type (flat + by-parent). |

### Schema model

| Class | Purpose |
| ----- | ------- |
| `DocSpecSchema` | A parsed document-schema definition. |
| `SectionTypeDef`, `PatternCheckDef`, `SubsectionConstraint` | Section-type definitions + their constraints. |
| `DocumentStructure`, `SectionDef`, `SubsectionDef`, `ForEachDef` | Document-structure rules. |
| `FormTypeDef`, `FormFieldDef` | Form-type definitions. |
| `SchemaInfo` | Schema summary (`id`, `version`, `path`, `source`; getters `fullId`/`filenameId`). |
| `SchemaSource` (enum) | `local`, `user`, `builtin` (3 values). |

### Schema loading & expansion

| Class | Purpose |
| ----- | ------- |
| `SchemaLoader`, `SchemaResolver`, `SchemaDiscovery`, `SchemaFilenameParser` | Schema discovery, resolution, and filename parsing. |
| `SchemaExpander` | Expands schema references/inheritance. |

### Skeleton & validation

| Class / Enum | Purpose |
| ------------ | ------- |
| `DocSpecsSkeletonGenerator` | Generates a document skeleton from a schema. |
| `DocSpecsValidator` | Validates a scanned document against its schema. |
| `AiValidator`, `PromptExpander` | AI-assisted validation + prompt expansion. |
| `ValidationError` | A validation failure (`message`, `lineNumber`, `sectionId`, `category`). |
| `ValidationErrorCategory` (enum) | `general`, `schemaDeclaration`, `sectionType`, `sectionId`, `structure`, `countLimit`, `nestingDepth`, `tags`, `textContent`, `format`, `forEach`, `aiValidation` (12 values). |

### Insert markers

| Class | Purpose |
| ----- | ------- |
| `InsertMarker`, `InsertMarkerParser`, `InsertMarkerProcessor` | Parse/process `<!--insert-->` markers for generated content. |

### Re-exports (`tom_doc_scanner`)

| Class | Purpose |
| ----- | ------- |
| `Section`, `Document` | Re-exported from `tom_doc_scanner` (the base types `SpecSection`/`SpecDoc` build on). |

## Example

```dart
import 'package:tom_doc_specs/tom_doc_specs.dart';

main() {
  // A schema-info record with derived getters.
  var info = SchemaInfo(
    id: 'quest-overview',
    version: '1.0',
    path: '/schemas/quest-overview.yaml',
    source: SchemaSource.builtin,
  );

  // A validation error with a category.
  var err = ValidationError(message: 'missing section', lineNumber: 12);

  return [info.fullId, info.filenameId, err.message, err.category.name];
  // ['quest-overview/1.0', 'quest-overview-1.0', 'missing section', 'general']
}
```

## Tests

Bridge coverage lives in
[`test/replay/test_d4rt_tom_doc_specs.d4rt`](../test/replay/test_d4rt_tom_doc_specs.d4rt),
run via the replay harness (`d4rt -run-replay <file> -test`, see
[`doc/testing.md`](testing.md)). The suite exercises the `ValidationError`
carrier (+ default `category`), the `ValidationErrorCategory` (12) and
`SchemaSource` (3) enums, the `SchemaInfo` `fullId`/`filenameId` getters, the
`SpecSectionType.empty` factory (`type`/`isEmpty`/`length`), and class-existence
for the scanner/factory/model/loader/validator/skeleton types.

> no globals/functions — plus a library re-export of `Section`/`Document` from

> scratch. **Naming note:** the upstream classes really are named
