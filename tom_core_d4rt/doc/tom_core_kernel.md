# tom_core_kernel bridge

The `tom_core_kernel` bridge exposes the Tom Framework core kernel
(`package:tom_core_kernel`) to D4rt scripts — the dependency-injection,
execution-context, HTTP/endpoint, isolate-pooling, logging, observable,
security, settings, resource, and timezone primitives that the rest of the
framework builds on. Bridges are generated by `d4rtgen` into
`lib/src/tom_core_kernel/tom_core_kernel_bridges.b.dart` and registered through
`TomDartscriptBridges.register` (see [`README.md`](../README.md)).

Scripts reach this surface by importing the upstream barrel:

```dart
import 'package:tom_core_kernel/tom_core_kernel.dart';
```

## Re-exported surfaces

The kernel barrel re-exports three upstream packages, so their bridged classes
are reachable through `tom_core_kernel` too. They are documented separately:

| Package | Doc | Examples of re-exported types |
| ------- | --- | ----------------------------- |
| `tom_basics` | [`tom_basics.md`](tom_basics.md) | `TomBaseException`, `TomLogLevel`, `TomLogger`, `TomPlatform`, `TomEnvironment`, `TomRuntime`; globals `tomLog`, `platform*`; `limited()` |
| `tom_reflection` | [`tom_reflection.md`](tom_reflection.md) | `Mirror`/`ClassMirror`/…, the capability classes, `StringInvocationKind` |
| `tom_crypto` | (upstream) | `RSAPublicKey`, `RSAPrivateKey`, `AsymmetricKeyPair`, `SecureRandom`; functions `rsaEncrypt`/`rsaDecrypt`/`rsaSign`/`rsaVerify`/`getRsaKeyPair` |

The remainder of this document covers the classes the kernel **owns**.

## Example

```dart
import 'package:tom_core_kernel/tom_core_kernel.dart';

main() {
  // A kernel exception.
  var ex = TomException('ERR_DEMO', 'Demo failure', parameters: {'code': 500});

  // A boxed observable value.
  var name = TomString('ada');

  // A principal role.
  var admin = TomRole(name: 'admin', entitlements: ['read', 'write']);

  // A MIME type.
  var mime = TomMimeType.json;

  return [ex.key, name.get(), admin.name, mime.subType];
  // ['ERR_DEMO', 'ada', 'admin', 'json']
}
```

## Tests

Bridge coverage lives in
[`test/replay/test_d4rt_tom_core_kernel.d4rt`](../test/replay/test_d4rt_tom_core_kernel.d4rt),
run via the replay harness (`d4rt -run-replay <file> -test`, see
[`doc/testing.md`](testing.md)). The suite exercises `TomException`,
`TomServerCallError`, `TomMimeType`/`TomHttpMethod`/`TomContentDisposition`,
the bean/connection/abort exceptions, the boxed observable scalars
(`TomString`/`TomInt`/`TomBool`), `TomObservable`, and the principal model
(`TomRole`/`TomGroup`/`TomEntitlement`).

> **Status (refactoring pass):** the generated bridges target `tom_d4rt`'s
> newer `BridgedClass` API (`isAssignable`/`hierarchyDepth`), which requires
> `tom_d4rt >= 1.8.19`; the committed `pubspec.lock` still pins `1.8.10`, so the
> binary/replay harness cannot be built until that pin is raised (tracked by the
> project-wide registration-verify and analyze/replay items), and the full
> registration additionally hits a cross-module `MarkdownParser`
> duplicate-registration clash. The bridged surface above was verified against
> the local `tom_core_kernel` source (pubspec `version: 1.1.0`; bridge
> regenerated 2026-06-15) and exercised in isolation against `tom_d4rt` ≥
> 1.8.19.
