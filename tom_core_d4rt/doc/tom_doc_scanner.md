# tom_doc_scanner bridge

The `tom_doc_scanner` bridge exposes the Tom Framework markdown document scanner
(`package:tom_doc_scanner`) to D4rt scripts — the markdown parser, the
section/document tree model, and the file/folder scanners. Bridges are
generated by `d4rtgen` into
`lib/src/tom_doc_scanner/tom_doc_scanner_bridges.b.dart` and registered through
`TomDartscriptBridges.register` (see [`README.md`](../README.md)).

Scripts reach this surface by importing the upstream barrel:

```dart
import 'package:tom_doc_scanner/tom_doc_scanner.dart';
```

The bridge covers all 6 symbols exported by `tom_doc_scanner.dart`
(7 classes — `ParsedHeadline` ships alongside `MarkdownParser` from the same
source file; no enums, globals, or top-level functions).

## Modules

### Scanners

| Class | Purpose |
| ----- | ------- |
| `DocScanner` | Scans a markdown file (`scanDocument`) or directory tree (`scanTree`) into the document model. |
| `DocScannerFactory` | Constructs configured `DocScanner` instances. |

### Markdown parser

| Class | Purpose |
| ----- | ------- |
| `MarkdownParser` | Static parser helpers: `parseHeadlines`, `extractText`, `generateId`, `calculateMaxDepth`. |
| `ParsedHeadline` | A parsed headline record (`level`, `lineNumber`, `rawHeadline`, `explicitId`, `text`, `fields`). |

### Document model

| Class | Purpose |
| ----- | ------- |
| `Section` | A headline + its content and nested subsections (`index`, `lineNumber`, `rawHeadline`, `name`, `id`, `text`, `fields`, `sections`). |
| `Document` | A scanned file root (extends `Section`) with file-location metadata (`filename`, `project`, `hierarchyDepth`, …). |
| `DocumentFolder` | A scanned directory (`foldername`, `documents`, `folders`). |

## Example

```dart
import 'package:tom_doc_scanner/tom_doc_scanner.dart';

main() {
  // Static parser helpers — no IO required.
  var id = MarkdownParser.generateId('My Section', 'parent', 2); // 'parent.2'
  var body = MarkdownParser.extractText('# Title\nbody line\n## Sub', 0, 1);

  // Section value carrier.
  var sec = Section(
    index: 0,
    lineNumber: 1,
    rawHeadline: 'Main',
    name: 'Main',
    id: 'main',
    text: body,
  );

  return [id, sec.name, sec.text]; // ['parent.2', 'Main', 'body line']
}
```

## Tests

Bridge coverage lives in
[`test/replay/test_d4rt_tom_doc_scanner.d4rt`](../test/replay/test_d4rt_tom_doc_scanner.d4rt),
run via the replay harness (`d4rt -run-replay <file> -test`, see
[`doc/testing.md`](testing.md)). The suite exercises the `ParsedHeadline` and
`Section` value carriers, the `MarkdownParser.generateId`/`extractText` static
helpers, and class-existence for `DocScanner`/`DocScannerFactory`/`Document`/
`DocumentFolder`.

> upstream `tom_doc_scanner` barrel (pubspec `version: 1.0.0`), which exports 6
> symbols across 6 source files. The bridge maps the full surface — 7 classes
> (`ParsedHeadline` shares `markdown_parser.dart` with `MarkdownParser`), no
> enums/globals/functions. There was no pre-existing replay test; one was
> authored from scratch against the real surface.
>
> The surface was verified **at the d4rt level** via an isolated single-bridge
> harness (register only `TomDocScannerBridge`, then `d4rt.execute` a script
> importing `package:tom_doc_scanner/tom_doc_scanner.dart`) under the resolved
> `tom_d4rt 1.8.23` — the script constructs `ParsedHeadline`/`Section`, calls the
> `MarkdownParser` static helpers, and returns the expected
> `[2, Title, api, Main, main, 0, title, parent.2, hello_world, body line]`. This
> confirms the bridge is **d4rt-loadable with no codegen defect** — the upstream
> package has **no `part of` files**, so there is no B4-style part-import that the
> CFE rejects. (`pubspec.lock` is gitignored; `tom_d4rt: any` resolves to 1.8.23,
> so the B1 lock-pin blocker does not apply.)
>
> **B2 origin note:** this bridge registers `MarkdownParser` — a symbol name
> that **also** appears in the `tom_md2latex` bridge (verified: `MarkdownParser`
> is registered in exactly `tom_doc_scanner` and `tom_md2latex`; the other
> exported symbols `Document`/`Section`/`DocScanner`/`DocScannerFactory`/
> `DocumentFolder`/`ParsedHeadline` are unique to this bridge, and `tom_md2pdf`
> does **not** register `MarkdownParser`). In the **full-binary**
> `d4rt -run-replay` (which registers *all* bridges at once) the two
> `MarkdownParser` registrations collide unless deduplicated by source URI; that
> is the **B2** cross-module duplicate-registration clash, deferred to the
> analyze/replay gate (`refactoring_plan.md` items 75-76). This bridge's
> `MarkdownParser` carries a
> distinct `sourceUri` (`package:tom_doc_scanner/src/markdown_parser.dart`), so
> the dedup machinery has the information it needs once B2 is wired up — but note
> the two `MarkdownParser`s are **different classes** (distinct upstream
> packages), so dedup-by-identity is not correct; this is a genuine name clash to
> resolve at item 75. `dart analyze lib/src/tom_doc_scanner` clean.
