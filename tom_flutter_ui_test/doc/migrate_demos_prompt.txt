# Tom UI Demo Migration Prompt

**Task:** Migrate demo files in `tom_ai/core/tom_flutter_ui_test/lib/widget_demos/` (demo_04 through demo_20) to use Tom* widget equivalents.

## Reference Documents
- Architecture: `_doc/tom/tom_ui_design_architecture.md`
- Widget list: `_doc/tom/tom_ui_flutter_widgets.md`
- Completed examples: `demo_02_inputs.dart`, `demo_03_selection.dart`

## Key Architecture Rules

### 1. tomId — Identity System
- `tomId` is the **plain unprefixed** identifier (e.g., `'demo.slider.volume'`)
- **NEVER** include `w-` prefix in `tomId` values — the framework adds it automatically via `TomNodeBase.resolveResourceBasePath()`
- The `w-` prefix is added at resolution time by `TomIdPrefix.prefixed()`

### 2. Widget Replacement Pattern
Replace Flutter SDK widgets with Tom* equivalents from `tom_flutter_ui`:
```dart
// Flutter SDK                        // Tom equivalent
ElevatedButton     →  TomElevatedButton
Switch             →  TomSwitch
Slider             →  TomSlider
Card               →  TomCard
AlertDialog        →  TomAlertDialog
DataTable          →  TomDataTable
ListView           →  TomListView
Text               →  TomText
Icon               →  TomIcon
Image              →  TomImage
TabBar             →  TomTabBar
CircularProgressIndicator → TomCircularProgressIndicator
// etc. — consult tom_ui_flutter_widgets.md for full mapping
```

### 3. Tom Widget Parameters
Tom widgets accept the same parameters as Flutter widgets PLUS:
- `tomId` — plain ID for identity/resources (String?)
- `tomGroup` — optional group membership (String?)

**IMPORTANT:** Tom* widgets MUST have the same public API as the underlying Flutter widget (except for the additional `tomId` and `tomGroup` parameters). If a Tom* widget has different parameter types or is missing parameters from the Flutter original, this is a **bug in tom_flutter_ui** that must be fixed.

### 4. Fixing Tom Widget Implementation Bugs
When you encounter a Tom* widget that doesn't match the Flutter SDK widget's API:

1. **Identify the mismatch** — Compare the Tom* widget constructor with the Flutter SDK widget
2. **Fix the Tom* implementation** — Update the widget in `tom_flutter_ui/lib/src/widgets/...` to match the Flutter API
3. **Common fixes needed:**
   - Missing parameters that exist in Flutter
   - Wrong parameter types (e.g., `labelText: String` when Flutter uses `label: Widget`)
   - Missing factory constructors (e.g., `.icon()`, `.filled()`)
4. **Test the fix** — Ensure the corrected widget compiles and works in the demo

Example bug fix:
```dart
// BUG: TomChip has labelText: String instead of label: Widget
// FIX: Update TomChip in tom_labels.dart to use label: Widget like Flutter's Chip

// Before (wrong):
class TomChip extends TomLabelBase {
  final String? labelText;  // WRONG
  
// After (correct):
class TomChip extends TomLabelBase {
  final Widget label;  // Matches Flutter's Chip
```

### 5. Demo Resources
For each Tom widget with a tomId, add corresponding entries to `demo_resources.dart`:
```dart
// Key pattern: '<tomId>.<suffix>'
'demo.slider.volume.label': 'Volume',
'demo.slider.volume.icon': 'mVolumeUp',
// Suffixes: label, hint, icon, tooltip, alt, title, subtitle
```

### 6. Code Sample Migration
Update documentation code blocks to show Tom* usage:
```dart
// Before (Flutter documentation)
Slider(value: 0.5, onChanged: (v) {})

// After (Tom documentation)
TomSlider(
  tomId: 'app.settings.volume',  // No w- prefix!
  value: 0.5,
  onChanged: (v) {},
)
```

### 7. Migration Workflow per Demo File
1. Read the demo file to understand which Flutter widgets it uses
2. Replace each Flutter widget with its Tom* equivalent
3. Add `tomId` parameter with a descriptive dot-separated path
4. If Tom* widget API differs from Flutter — **fix the Tom* widget implementation first**
5. Update code samples in `const String _*Code = '''...'''` sections
6. Add resource entries to `demo_resources.dart` for all new tomIds
7. Run `dart analyze` to verify no errors
8. If errors occur due to API mismatch, fix the tom_flutter_ui widget
